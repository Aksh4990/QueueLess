# QueueLess validation plan

This plan tests the concept before any live service is built. The prototype itself does not contain research results.

## Questions for students

- When do queues most affect your campus day?
- How do you decide what and where to buy when a break is short?
- Would you use a pickup window, and what would make you trust it?
- What would you do if an item became unavailable after you ordered?

## Questions for canteen operators

- When are the busiest periods, and how does demand vary?
- Could advance requests be prepared without slowing walk-up customers?
- What pickup window size, order limit and handoff process would be workable?
- How should sold-out items, late pickups and cancellations be handled?

## Small supervised pilot

If interviews support the problem and an operator agrees, run a limited manual trial with a small menu and a clearly stated order cap. Have staff confirm each request and provide a realistic pickup window. Do not accept payment through this prototype.

## Measures to record

- Student-reported usefulness and intent to use again.
- Difference between promised and actual pickup time.
- Orders fulfilled, changed, cancelled or not collected.
- Operator-reported workload and effect on walk-up service.

Agree on collection and consent before recording any participant data. Share only aggregated results in a class presentation. Stop the pilot if it disrupts normal service or creates unsafe crowding.

## Decision after validation

Continue only if students report a recurring problem and the canteen identifies a workable process. Otherwise revise the pickup model or the target situation before adding software infrastructure.
